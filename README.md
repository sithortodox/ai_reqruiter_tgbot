# AI Interview Bot — Telegram-бот первичного AI-собеседования

Бот проводит первичное собеседование кандидатов в Telegram, собирает контакты и
резюме, выполняет AI-анализ через OpenAI-совместимый API, маршрутизирует
результат (`recommended` / `not_recommended` / `manual_review`), отправляет
карточку в закрытый чат рекрутеров и ведёт веб-панель администрирования.

Соответствует техническому заданию `TZ.md`.

## 1. Установка и запуск

### Требования

- Python 3.12+ (в Docker используется `python:3.12-slim`)
- Docker + Docker Compose (рекомендуется) либо локальный Python
- PostgreSQL 16 (в Docker — контейнер `db`)

### Запуск через Docker Compose (рекомендуется)

```bash
# 1. Скопировать и заполнить конфигурацию
cp .env.example .env
$EDITOR .env

# 2. Собрать и запустить (миграции применяются автоматически при старте)
docker compose up -d --build

# 3. Просмотр логов
docker compose logs -f app

# 4. Остановка
docker compose down          # данные сохраняются в томе pgdata
docker compose down -v       # ⚠️ удалить тома (потеря данных)
```

Сервисы:

| Сервис | Назначение | Порт |
|---|---|---|
| `db` | PostgreSQL 16 | 5432 (внутри сети) |
| `app` | Бот + веб-панель | `ADMIN_WEB_PORT` (по умолчанию 8080) |

Каталог `./storage` монтируется в контейнер — там хранятся файлы резюме.

### Запуск локально (без Docker)

```bash
# Виртуальное окружение
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# Конфигурация (для локального запуска достаточно SQLite)
cp .env.example .env
$EDITOR .env
# DATABASE_URL=sqlite+aiosqlite:///./dev.db

# Миграции
alembic upgrade head

# Демо-вакансия, вопросы и промпт (опционально, первый запуск)
python3 -m app.seed

# Запуск бота (long polling + веб-панель + фоновые воркеры)
python3 -m app.main
```

### Статус и healthcheck

- `GET /healthz` — панель отвечает без авторизации (для Docker HEALTHCHECK);
- `GET /health` — с авторизацией, дополнительно проверяет доступность БД.

### Команды бота (для кандидата)

| Команда | Действие |
|---|---|
| `/start` | Начать или продолжить интервью |
| `/cancel` | Отменить текущее интервью |
| `/skip` | Пропустить необязательный шаг (резюме) |
| `/help` | Справка |

## 2. Создание Telegram-бота и токен

1. Откройте [@BotFather](https://t.me/BotFather) в Telegram.
2. Отправьте `/newbot`, задайте имя и username бота.
3. Получите токен вида `123456789:AAF...` — это значение `BOT_TOKEN`.
4. Заполните в `.env`:

```dotenv
BOT_TOKEN=123456789:AAF...
ADMIN_IDS=123456789,987654321
```

`ADMIN_IDS` — Telegram ID пользователей с административными правами
(узнать свой ID можно через [@userinfobot](https://t.me/userinfobot)).

**Важно:** бот работает в режиме **long polling** — отдельная настройка
webhook не требуется, выход в интернет наружу не нужен.

5. Перезапустите приложение. Проверка токена выполняется при старте; при
   некорректном токене приложение завершается с понятным сообщением.

## 3. Подключение LLM API

Адаптер работает с любым **OpenAI-совместимым** `chat/completions` API.

```dotenv
LLM_PROVIDER=openai_compat
LLM_API_KEY=sk-...
LLM_MODEL=gpt-4o-mini
LLM_BASE_URL=https://api.openai.com/v1
LLM_TIMEOUT_SECONDS=90
LLM_MAX_RETRIES=3
LLM_MAX_INPUT_CHARS=12000
# Для расчёта расходов (USD за 1K токенов), опционально:
LLM_PRICE_INPUT_PER_1K=0.00015
LLM_PRICE_OUTPUT_PER_1K=0.0006
```

Примеры `LLM_BASE_URL`:

| Провайдер | LLM_BASE_URL | LLM_MODEL |
|---|---|---|
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |
| Совместимый шлюз | `https://gateway.example.com/v1` | см. документацию шлюза |

**Демо-режим:** если `LLM_API_KEY` пуст, адаптер возвращает синтетический
отчёт с эвристиками — этого достаточно для разработки и тестов, но **нельзя
использовать для реального отбора**. Приложение предупреждает об этом в логах
при старте.

Расход токенов и стоимость фиксируются в таблице `ai_reports`
(`input_tokens`, `output_tokens`, `cost_usd`, `duration_ms`) и видны в
карточке кандидата и журнале аудита.

## 4. Закрытый чат рекрутеров

1. Создайте в Telegram группу (закрытый чат) и добавьте туда бота.
2. Перешлите в группу любое сообщение от имени бота или добавьте бота
   и отправьте команду, чтобы получить ID чата (например, через
   [@getidsbot](https://t.me/getidsbot) внутри группы). ID вида
   `-1001234567890`.
3. Заполните в `.env`:

```dotenv
RECRUITERS_CHAT_ID=-1001234567890
```

4. При получении `RECRUITERS_CHAT_ID` приложение завершает запуск с ошибкой —
   карточки не будут отправляться.

Отправка карточек идёт через **outbox**: каждое уведомление получает
`idempotency_key`, поэтому повторная обработка события Telegram не создаёт
дублей. Недоставленные сообщения повторяются автоматически.

## 5. Изменение вопросов и критериев оценки

### Вопросы интервью

Вопросы заданы в `app/seed.py` (`DEMO_QUESTIONS`). Формат:

```python
{
    "id": "q_years",              # уникальный идентификатор
    "text": "Сколько лет ...?",   # текст вопроса
    "order": 1,                   # порядок в опросе
    "answer_type": "text",        # тип ответа
    "required": True,             # обязателен ли ответ
    "max_length": 1500,           # лимит символов
    "enabled": True,              # включён ли вопрос
}
```

Вопросы версионируются: при старте сессии создаётся снимок сценария
(`scenario_snapshot`, `scenario_versions`), поэтому правка вопросов **не
ломает** уже идущие интервью и не меняет результаты прошедших.

### Системный промпт AI

Файл `prompts/default_system_prompt.md`. Поправки также версионируются
(`prompt_versions`): изменение промпта не меняет результаты старых интервью.

### Критерии оценки и маршрутизация

Конфигурация вакансии — `evaluation_config` в `app/seed.py`:

```python
"evaluation_config": {
    "score_threshold": 7,          # порог рекомендации (1..10)
    "weights": {...},              # веса критериев
    "stop_factors": [...],         # стоп-факторы (автоотказ)
    "timeout_minutes": 60,
    "reminder_minutes": 30,
    "max_file_size_mb": 10,
    "allowed_file_types": [".pdf", ".docx", ".txt"],
    "texts": {...},                # тексты сообщений кандидату
}
```

После первого запуска вакансии хранятся в БД (таблица `vacancies`) и
редактируются через веб-панель `/vacancies`.

### Демо-вакансия

```bash
python3 -m app.seed
```

Создаёт вакансию `backend-python`, вопросы и промпт по умолчанию.
Демо-данные синтетические — согласуйте реальные с заказчиком перед запуском.

## 6. Архитектура и модель данных

### Структура проекта

```text
ai-recruiter-bot/
├── app/
│   ├── bot/                  # aiogram: handlers, middlewares, keyboards, dispatcher
│   ├── services/             # бизнес-логика
│   │   ├── interview_service.py     # диалоговый автомат, переходы
│   │   ├── candidate_service.py     # профиль кандидата
│   │   ├── resume_service.py        # парсинг PDF/DOCX/TXT, анти prompt-injection
│   │   ├── ai_analysis_service.py   # вызов LLM, валидация JSON-схемы, ретраи
│   │   ├── routing_service.py       # recommended / not_recommended / manual_review
│   │   ├── notification_service.py  # outbox, идемпотентность
│   │   ├── dispatch_service.py      # доставка очереди
│   │   ├── timeout_service.py       # тайм-ауты, напоминания
│   │   └── retention_service.py     # ретеншн и удаление ПД
│   ├── integrations/llm/     # адаптер LLM (OpenAI-совместимый) + JSON-схема
│   ├── database/             # models, repositories, base
│   ├── admin/                # FastAPI веб-панель + Jinja2-шаблоны
│   ├── config.py             # Settings (pydantic-settings) + валидация
│   ├── logging_conf.py       # логирование с расходом токенов
│   ├── seed.py               # демо-вакансия, вопросы, промпт
│   └── main.py               # точка входа
├── alembic/                  # миграции
├── prompts/                  # системный промпт
├── tests/                    # pytest (46 тестов)
├── scripts/entrypoint.sh     # миграции до старта
├── Dockerfile
├── compose.yaml
├── requirements.txt
├── .env.example
├── .gitignore
└── README.md
```

### Диалоговый автомат

```text
new → collecting_data → collecting_resume → interviewing
    → analyzing → completed | analysis_failed | manual_review
    (cancel/expire возможны на всех шагах)
```

Переходы валидируются через `ALLOWED_TRANSITIONS` (`app/database/models.py`);
нелегальный переход вызывает `TransitionError`.

### Модель данных (таблицы)

| Таблица | Назначение |
|---|---|
| `candidates` | профиль кандидата (Telegram ID, имя, контакт, статус) |
| `vacancies` | вакансии, требования, `evaluation_config`, версии сценария/промпта |
| `scenario_versions` | версии сценария вопросов |
| `prompt_versions` | версии системного промпта |
| `interview_sessions` | сессии: состояние, шаг, снимок вопросов, идемпотентность апдейтов |
| `interview_answers` | ответы кандидата (уникальность `session_id + question_id`) |
| `resumes` | резюме: файл, извлечённый текст |
| `ai_reports` | отчёт AI: score, recommendation, JSON, токены, стоимость, статус |
| `outgoing_messages` | outbox доставки с `idempotency_key` |
| `audit_logs` | журнал событий |
| `settings` | настройки веб-панели |

### Формат JSON-отчёта AI

Схема — `app/integrations/llm/schema.py` (`AIReport`): итоговая оценка 1–10,
`recommendation`, сильные стороны, пробелы, обоснование, соответствие
требованиям. Невалидный ответ модели отклоняется и повторяется; при исчерпании
попыток сессия уходит в контролируемое состояние (`analysis_failed` /
`manual_review`), **автоматический отказ не происходит**.

## 8. Резервное копирование и восстановление

### PostgreSQL (Docker)

Каталог `./backups` смонтирован в контейнер `db` как `/backups`.

```bash
# Бэкап
docker compose exec db sh -c \
  'pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB" | gzip > /backups/backup_$(date +%F_%H%M).sql.gz'

# Восстановление
gunzip -c ./backups/backup_2025-01-01_1200.sql.gz | \
  docker compose exec -T db psql -U "$POSTGRES_USER" "$POSTGRES_DB"
```

### Файлы резюме

Каталог `./storage` — обычные файлы на хосте; включите его в план бэкапа.

### Расписание (пример cron)

```cron
0 3 * * * cd /path/to/bot && docker compose exec -T db sh -c 'pg_dump -U recruiter recruiter' | gzip > backups/backup_$(date +\%F).sql.gz
```

Восстановление на новый сервер: заполнить `.env`, запустить
`docker compose up -d` — миграции применятся автоматически, данные подхватятся
из тома `pgdata` или из бэкапа.

## 9. Известные ограничения и доработки

### Ограничения (согласно решениям заказчика)

1. **Демо-конфигурация.** Параметры от заказчика пока не получены: вакансия,
   вопросы и промпт — синтетические демо-данные (`app/seed.py`). Не
   использовать для реального отбора без согласования (раздел 17 TZ).
2. **Демо-режим LLM.** Без `LLM_API_KEY` аналитика возвращает синтетический
   отчёт с эвристиками. Реальная интеграция активируется заполнением ключа.
3. **Long polling.** Выбран для первой версии: не требует белого IP и
   настройки webhook. При переходе на несколько инстансов потребуется webhook.
4. **Шифрование ПД.** Поле `ENCRYPTION_KEY` зарезервировано; на данный момент
   контакты хранятся в БД в открытом виде — расшифровка/шифрование полей
   запланировано как доработка.
5. **Один вакансный сценарий в демо.** Мультиязычность и распределение
   кандидатов по нескольким вакансиям через панель — в плане доработок.

### Необходимые доработки перед промышленным запуском

- Заполнить параметры заказчика (раздел 17 TZ): вакансия, требования,
  вопросы, провайдер LLM, чат, ID админов, место размещения, сроки хранения
  ПД, порог оценки.
- Согласовать условия обработки ПД с LLM-провайдером (раздел 7 TZ).
- Реализовать шифрование полей ПД (`ENCRYPTION_KEY`).
- Настроить мониторинг логов и алертинг на ошибки доставки/анализа.
- Провести пилотный прогон на синтетических кандидатах и сравнить оценки AI
  с ожиданиями рекрутеров (раздел 13 TZ).

## Конфигурация

Полный шаблон — `.env.example`. Ключевые параметры:

| Переменная | Назначение | Обязательна |
|---|---|---|
| `BOT_TOKEN` | токен Telegram-бота | да |
| `ADMIN_IDS` | Telegram ID администраторов | да |
| `RECRUITERS_CHAT_ID` | ID закрытого чата рекрутеров | да |
| `DATABASE_URL` | строка подключения к БД | да (есть default) |
| `LLM_API_KEY` | ключ LLM API | нет (иначе демо-режим) |
| `LLM_BASE_URL` / `LLM_MODEL` | эндпоинт и модель | нет |
| `RETENTION_DAYS` | срок хранения ПД в днях | нет (365) |
| `ADMIN_WEB_ENABLED` / `ADMIN_WEB_PORT` | веб-панель | нет |
| `ADMIN_USERNAME` / `ADMIN_PANEL_PASSWORD` | доступ к панели | рекомендуется |
| `LOG_LEVEL` | уровень логов | нет (`INFO`) |

При отсутствии обязательного параметра приложение завершается с понятным
сообщением об ошибке (раздел 10 TZ).

**Секреты не коммитятся:** файл `.env` в `.gitignore`. Заполняйте `.env` вручную
и передавайте заказчику безопасным способом.
